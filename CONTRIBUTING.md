# Contributing

[Repository](README.md)

Use a descriptive feature branch. Keep exercises unimplemented in the reference branch, so readers can attempt them. State the change pressure, stable behaviour, evidence and limits in a review.

Run the README checks and the relevant CLI before submitting. Add tests for meaningful behaviour, especially boundary or failure cases, rather than asserting that a particular number of abstractions exists. Keep policies independent of concrete suppliers and keep composition visible.

Use deterministic local fixtures. Do not introduce real credentials, services or hidden persistence into teaching examples. Update links and scope claims alongside the code.
